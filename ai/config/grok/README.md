# Grok status line

`statusline.js` reads Grok's JSON from stdin and prints the custom status row.
The native config is generated by `ai/setup.py`; do not copy the `__HOME__` command
from the preference snapshot into live configuration.

## Windows error 123

The reported live setting was `node C:/Users/tHeSiD/.grok/statusline.js`.
Grok's launcher first calls `Command::new` with the entire configured string.
The embedded drive colon can produce Windows error 123 (invalid filename syntax).
That error is returned without the fallback that runs a command through a shell.
The JavaScript has not started when this error appears.

The Windows installer therefore generates `statusline.cmd` alongside the JavaScript
and sets `ui.status_line.command` to that file's absolute path. There are no command
arguments or shell quotes in the configured filename; the batch launcher quotes
the discovered Node executable and uses `%~dp0statusline.js` for its sibling script.
Node discovery checks current PATH, then persisted Windows PATH if the calling
editor/agent has an older environment. No hardcoded drive is needed in the repo.

On macOS/Linux the generated setting remains a quoted Node command. Restart Grok
after changing `ui.status_line`, which it reads at startup.

The live Windows setting and launcher were updated after a private backup. A native
process launch with documented mock JSON returned exit 0, printed a nonempty row
and had no stderr. This checks the launcher/script contract; confirmation inside
Grok requires restarting its active session. The JavaScript uses the documented
workspace/model/context/session-usage/cost fields with guards for missing values;
Git worktree counts are obtained locally.
